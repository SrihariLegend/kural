# Evidence reshapes Reef into a tested hybrid

Most of Reef's borrowed ideas hold up only as experiments. A few are solid enough to adopt now, and the design misreads two of its sources. **Adopt now**: the attention details from Needle 3 (QK-norm, a sigmoid output gate, 3-tap q/k/v convolutions), a gated delta-rule memory with L2-normalised keys used within a session, supervision at every pass with a hard cap on passes, execution-guided pruning, a confidence head trained on sandbox outcomes, and an integer (W8A8, AVX-VNNI) inference kernel. **Test, each as its own measured step**: the BDH core, the sparse lift, k-WTA, Engram tables, the JEPA loss, extra recurrent passes, fast weights kept across sessions, and execution RL. **Skip**: BitNet ternary training, differentiable logic gates, VSA components, product-key memory as a large store, HRM's hierarchy, Mamba-2/GLA/RetNet as the memory, and Jev. Two misreadings matter most. Needle 3's Hadamard MLP is a square mixer with about 25K parameters per layer, not a lift to a wide sparse layer ([Cactus](https://cactuscompute.com/blog/simple-attention-networks)). And BDH's published results cover a ReLU lift with plain additive Hebbian memory, not Reef's k-WTA, delta rule and structured lift ([BDH](https://arxiv.org/html/2509.26507)). The stakes are concrete. On the cleanest execution-checked bash benchmark, Qwen2.5-Coder-7B scores about **0.61-0.62**, Llama-3.1-8B **0.46-0.56** and GPT-4o **0.74** ([Westenfelder et al.](https://aclanthology.org/2025.naacl-long.555.pdf)), and **no model under 100M parameters has ever been scored by execution on such a set**. The literature cannot tell kural whether Reef will win; only kural's own measurements can. That makes the evaluation harness and the data work, not the novel core, the first things to build.

## The bar is about 0.6 execution accuracy, and no small model has been measured against it

The usable benchmarks come from one ancestor. NL2Bash has 9,305 pairs scraped from StackOverflow, and its data has been under MIT since 2020 ([NL2Bash repo](https://github.com/TellinaTool/nl2bash)). It is badly noisy: when NL2Bash-derived pairs were hand-audited, **113 of 224 (50.4%) were invalid** in prompt, command or environment ([Westenfelder et al.](https://aclanthology.org/2025.naacl-long.555.pdf)). Almost every later test set descends from NL2Bash. NLC2CMD (NeurIPS 2020) used a metric that **ignores arguments entirely** and admits its phase-1 test set may overlap public training data ([NLC2CMD report](https://arxiv.org/html/2103.02523v2)). InterCode-Bash (200 tasks in Docker) defined the standard continuous execution reward: TF-IDF similarity of stdout, plus the symmetric difference of changed files, plus md5 matches ([InterCode](https://arxiv.org/html/2306.14898v3)). But its reset script let the two environments drift apart. Westenfelder et al. fixed that and released **NL2SH-ALFA**: a 600-pair, hand-verified test set with Docker environments and a 40,939-pair training set, both MIT ([NAACL 2025](https://aclanthology.org/2025.naacl-long.555.pdf)). They also showed that judging equivalence without running the commands fails. A GPT-4 judge without execution had recall 0.51; with execution outputs it reached **0.95 accuracy** against human labels. IBM's 125 hand-written cases use per-test prologue and epilogue scripts and fail any command that creates spurious system files ([Vo et al.](https://arxiv.org/pdf/2405.06807)). That is the most trustworthy design for side effects.

The published numbers on ALFA split cleanly by size. The paper's own summary is that "model size remains the dominant factor".

| Model (NL2SH-ALFA test) | Base | Best wrapper (parse / ICL / fine-tune) |
|---|---|---|
| llama-3.2-1b | 0.12 | 0.37 |
| qwen2.5-coder-0.5b | 0.10 | 0.36 |
| llama-3.2-3b | 0.17 | 0.49 |
| llama-3.1-8b | 0.46 | 0.56 |
| qwen2.5-coder-7b | 0.61 | 0.62 |
| gpt-4o | 0.74 | 0.73 |

Source: [Westenfelder et al.](https://aclanthology.org/2025.naacl-long.555.pdf). Some rows were rebuilt from PDF columns that extracted out of order, so check them against the paper before quoting.

For Reef, the hopeful detail in that paper is the failure mode. For models under 7B, the dominant error is **output format** (markdown and the like), and with fine-tuning a 0.5B model matches the base score of a 3B model. Reef removes format errors by construction, because it decodes under a grammar into a typed program. In the older, argument-blind competition, small specialised systems did well. NLC2CMD was won by an ensemble of five six-layer transformers (0.532), ahead of a fine-tuned GPT-2 (0.513), and TF-IDF retrieval alone reached 0.43-0.47 ([NLC2CMD report](https://arxiv.org/html/2103.02523v2)). Other execution numbers give a sense of the spread. Zero-shot single-line bash: GPT-4o 84%, Mistral-7B 62% ([Vo et al.](https://arxiv.org/pdf/2405.06807)). InterCode single-turn success: GPT-4 34%, Vicuna-13B 16% ([InterCode](https://arxiv.org/html/2306.14898v3)). The honest reading: a small specialist beating 8B models is **plausible but unmeasured**. Reef's best chance is kural's own people-written set, where grounding to installed tools and the local file tree gives it information the LLM baselines lack. A fair comparison therefore has four parts. Give the 8B/14B baselines their best published wrapper: markdown parsing, about 10 retrieved examples and, for Llama, constraining the first token to a utility. Also run a variant where the baselines receive kural's grounding context. Score every system with the same sandbox checker. Report coverage and declines separately, so that declining cannot inflate accuracy.

## Memory and attention: the delta rule earns its place, but softmax keeps the exact jobs

Among fixed-state layers, the delta rule recalls best because it can overwrite a value instead of piling new writes on top. On the MAD synthetic suite, DeltaNet scores 100 on in-context recall and selective copy. Its fuzzy recall is 35.7, against Mamba's 6.7 and GLA's 6.9 ([Yang et al. 2024](https://arxiv.org/html/2406.06484)). Gated DeltaNet adds a data-dependent decay and leads pure recurrent models on commonsense (55.32 vs Mamba-2 54.89 and RetNet 52.02 at 1.3B) ([Gated DeltaNet](https://arxiv.org/html/2412.06464v3)). RWKV-7 uses a generalised delta rule and claims state tracking, but it starts at 0.19B and has no head-to-head recall comparison ([RWKV-7](https://arxiv.org/abs/2503.14456)). The gap to softmax does not close with scale: at 1.3B, DeltaNet scores **17.2 on FDA against 27.4 for a transformer** ([Yang et al. 2024](https://arxiv.org/html/2406.06484)). There is also a proof that any fixed state below about L·log D bits fails to copy a length-L string more than half the time ([Jelassi et al.](https://arxiv.org/html/2402.01032v2)). Hybrids win consistently. DeltaNet plus two global attention layers beats the transformer on all three recall tasks (SWDE 71.0 vs 66.6) ([Yang et al. 2024](https://arxiv.org/html/2406.06484)). About 10% attention layers gives Mamba-2 its best perplexity ([Mamba-2](https://arxiv.org/html/2405.21060)). Evidence at small scale is thin. The only language result under 50M parameters is Schlag et al.'s model of about 40M, where the delta rule beats additive linear attention by about 2.8 perplexity (34.1 vs 37.1 on validation) and sits roughly 1.4 behind softmax ([Schlag et al.](https://arxiv.org/html/2102.11174v3)). Zoology's tiny 2-layer models show softmax solving associative recall at width 64, where gated convolutions need width at least equal to the number of pairs ([Zoology](https://arxiv.org/html/2312.04927)).

These results change Reef in four specific ways. First, **normalise the keys**: L1 to L2 normalisation moved DeltaNet from 31.12 to 28.03 perplexity, and unnormalised delta networks diverged ([Yang et al. 2024](https://arxiv.org/html/2406.06484)). Reef's k-WTA binary key has ‖k‖² = k, so a write with β near 1 is unstable for any k above 2. Second, make the decay λ a per-token gate rather than a slow constant. Titans' ablation ranks forgetting as the most important part of its memory (27.01 → 29.04 perplexity without it) ([Titans](https://arxiv.org/html/2501.00663v1)). Third, drop "β = importance × surprise". The delta term already writes only the residual v − S·k, so that product counts surprise twice. Use a learned σ(W·x) and, if wanted, multiply in an external trust factor. Fourth, the 3-tap convolution is worth keeping. It took DeltaNet's FDA score from 4.5 to 12.8 at 340M, and removing it hurt Titans; it gave GLA nothing ([Yang et al. 2024](https://arxiv.org/html/2406.06484)).

Capacity follows the Hopfield picture. A linear or delta memory holds about d_k orthogonal associations: with d_k = 64, errors started near 60 keys ([Schlag et al.](https://arxiv.org/html/2102.11174v3)). Softmax retrieval, the modern Hopfield form, has capacity exponential in dimension ([Santos et al.](https://arxiv.org/pdf/2402.13725)). In Reef's sparse space (k = 512 of N = 32k), random codes overlap with a cosine of about 1.6%, which supports roughly hundreds of items per head. Learned codes cluster, though, so real interference will be worse. The state is also far bigger than the budget table admits. N × d_v at 32k × 128 is **4.2M numbers per head, larger than the whole model**. And 8-bit storage would round small-β writes to zero, which silently disables the planned "loosen rather than erase" behaviour.

Test-time training is narrower than the design assumes. TTT, Titans and TTT-E2E all show gains from learning *within one sequence*, at 125M-3B parameters ([TTT](https://arxiv.org/abs/2407.04620); [TTT-E2E](https://arxiv.org/abs/2512.23675v1)). No source measures a benefit from fast weights carried *across* sessions. Within-session fast weights are the same computation as long-context linear attention, so they are sound, provided Reef trains on sequences shaped and sized like real sessions. Persisting them across sessions brings staleness, drift and poisoning risks that nobody has measured. The cheap fix for exact session facts ("the same file as before") is a **bounded exact softmax buffer** over the session. At 2,000 tokens it costs about 256k multiply-adds per query and about 256 KB of int8 cache. That is affordable on a CPU, and it matches the hybrid evidence.

## The sparse core rests on three untested departures from BDH, one of them a misreading

BDH really is what Reef's core imitates: a weight-shared stack with d = 256 lifted by ReLU into n ≈ 32k positive neurons. It runs unnormalised linear attention with Q = K = the sparse code, and gates the result with x ⊙ y, the "modus-ponens" product of the current code and the recalled code. About 5% of neurons are active, from ReLU alone with no L1 penalty ([BDH paper](https://arxiv.org/html/2509.26507); [bdh.py](https://raw.githubusercontent.com/pathwaycom/bdh/main/bdh.py)). The authors claim GPT-2 parity from **10M to 1B parameters** ([arXiv 2509.26507](https://arxiv.org/abs/2509.26507)). No independent replication was found, and no result exists below 10M, which is Reef's range. Reef then makes three changes that BDH's results do not cover: k-WTA at 1-2% instead of ReLU at about 5%, a decaying delta-rule write instead of additive Hebbian accumulation, and a structured lift instead of BDH's dense matrices, which hold most of its ≈3nd parameters. Cost matters too. As published, BDH at n = 32k, d = 256 costs about 25M multiply-adds per token per layer, roughly 35 times Reef's 0.7M budget. So Reef's arithmetic works only through the very departures that are untested. BDH-CQ adds nothing usable. It reports 29.5% pass@2 on ARC-AGI-1 at 150M parameters, but its dimensions and update rules are proprietary, its cost figures (computed on H200 GPUs) contradict each other, and language is untested ([BDH-CQ](https://arxiv.org/html/2608.09888)).

The structured lift is where the design misreads its source. ARCHITECTURE.md cites "Needle's Hadamard MLP" for a D = 128 → N = 8k-32k lift. In Cactus's code, that MLP is **square**: width is the next power of two above d_model, made of three Kronecker products of 32×32 factors initialised to Walsh-Hadamard, with diagonal scales and a rank-8 modulation, and its output is cut back to d_model. Cactus quotes about **25K parameters per layer**, against about 4.7M for a dense FFN ([Cactus blog](https://cactuscompute.com/blog/simple-attention-networks)). Needle 3 is really attention plus lookup tables: **70.8M of its 121M parameters are Engram tables** ([Needle page](https://cactuscompute.com/needle)). Cactus's own FFN-removal study points against "a wide lift carries knowledge". At matched parameters, dropping the FFN costs only **0.0055 nats** ([Cactus blog](https://cactuscompute.com/blog/simple-attention-networks)). The arithmetic is worse still. A Kronecker lift from 128 to 16,384 neurons has about **3K free parameters**, and each neuron computes a_iᵀ·X·b_j. Top-k then selects a near-grid formed by crossing two small codes, so "one concept per neuron" and "low interference" both fail. The broader evidence agrees. Full-rank structures without parameter sharing (Monarch, BTT) match dense: Monarch GPT-2 Small reaches 20.7 perplexity against 20.6 for dense, with 58% of the parameters ([Monarch](https://arxiv.org/pdf/2204.00595)). Structures that share parameters, Kronecker among them, scale worse in compute-optimal tests on GPT-2 models from 120k to 76M parameters ([Potapczynski et al.](https://arxiv.org/html/2410.02117v2)). The most promising cheap way to get a 16k-neuron sparse layer is **product-key-style selection**. Two sets of 128 sub-keys yield an exact top-k over 16,384 combinations for about 16K multiply-adds ([PKM](https://ar5iv.labs.arxiv.org/html/1907.05242)).

k-WTA trains, with caveats. Numenta trained it with straight-through gradients and duty-cycle boosting, and saw better noise robustness at equal accuracy (Speech Commands 96.65 vs 96.37). But the comparison was not size-matched, and the sparse networks ran at the **same speed** as dense ones ([Numenta](https://arxiv.org/pdf/1903.11257); [forum critique](https://discourse.numenta.org/t/how-can-we-be-so-dense-the-benefits-of-using-highly-sparse-representations/5693)). Google's Spark Transformer gets real CPU speedups (1.64-1.86× in decode and prefill) from about 8% active neurons, using a linear-time statistical top-k ([Spark](https://arxiv.org/abs/2506.06644v2)). Reef's 1-2% is sparser than either, so dead neurons are the main risk, and the fraction of neurons that ever fire should be logged.

Lookup memories follow the same pattern: real gains at scale, little evidence at Reef's size. DeepSeek's Engram-27B gains +3.0 MMLU and +5.0 BBH over an iso-FLOP MoE, but disabling it keeps 93% of reading comprehension against 29% of TriviaQA. **It stores facts, not understanding** ([Engram](https://arxiv.org/html/2601.07372v1)). Reef's planned 16k-slot tables sit at the small end of every curve. In PKM's ablation, a 16k-slot memory improved perplexity from 22.98 to 22.80; a million slots got 17.98 ([PKM](https://ar5iv.labs.arxiv.org/html/1907.05242)). The only result below 50M is synthetic. There, input-side 3-gram tables helped a 2.4M model, while output-side n-grams hurt it ([Over-Tokenized Transformer](https://arxiv.org/html/2501.16975v2)). Hashed exact n-grams also reward surface form, which is the opposite of Reef's paraphrase problem. VSAs offer a lens, not a component. The survey literature has no semantic-parsing results ([Kleyko et al.](https://arxiv.org/abs/2112.15424)), and the delta-rule outer product already is a learned slot-value binding.

## Recursion buys a training recipe, not demonstrated reasoning in language

Tiny Recursive Models are real and striking. A 7M, 2-layer network reaches 87.4% on Sudoku-Extreme and 44.6% on ARC-AGI-1, against HRM's 55.0% and 40.3% at 27M ([TRM](https://arxiv.org/html/2510.04871)). The ablated, robust parts are training choices. Full backprop through the last recursion cycle scores 87.4% against 56.5% for HRM's one-step gradient; EMA scores 87.4 against 79.9 without it; and a single small network beats two separate ones. The claim that recursion "beats far larger language models" does not survive the critiques. ARC Prize found HRM's hierarchy had minimal effect: a plain transformer came within about 5 points, and the outer refinement loop was the largest factor ([ARC Prize](https://arcprize.org/blog/hrm-analysis)). A re-analysis of TRM found that a blank puzzle ID gives **0%**, that 1,000-sample voting adds about 11 points, and that "most final accuracy appears at the first recursion step" ([arXiv 2512.11847](https://arxiv.org/abs/2512.11847)). The only autoregressive test found **no reliable gain** over compute-matched transformers ([arXiv 2603.08082](https://arxiv.org/abs/2603.08082)). One finding does transfer: training with 16 refinement loops raised single-loop inference by more than 15 points ([ARC Prize](https://arcprize.org/blog/hrm-analysis)). That is a direct argument for supervising every Reef pass.

Geiping et al.'s recurrent-depth model shows that iteration can matter, at a scale 500 times larger: on GSM8K at 3.5B, r = 1 scores 0% and r = 32 scores 42.1%. It also shows how training fails. In one bad run all tokens collapsed to one state; in another, the model ignored the recurrence, with identical perplexity at r = 1 and r = 32. The fixes were sandwich norm, a 10× lower learning rate, a randomly sampled r and truncated backprop ([Geiping et al.](https://arxiv.org/html/2502.05171)). Its latent trajectories include **orbits** that never converge. That is direct evidence for Reef's "stop when stable" risk, and k-WTA adds a new one: a single neuron at the k boundary can flip forever. Geiping's exit rule is simple. Stop when the KL divergence between successive steps falls below 5×10⁻⁴; this lost almost nothing (MT-Bench 5.63 → 5.56). Learned halting is reported unstable ([PonderNet](https://arxiv.org/pdf/2107.05407)). On compositional parsing benchmarks, Universal Transformer results depended more on training details than on weight sharing ([Csordás et al.](https://arxiv.org/pdf/2108.12284)).

Needle's ladder exits support the same recipe. Training each step at a random depth with probability 0.2, plus KL toward the full model, improved full-depth loss by 3.9% (1.958 vs 2.037) and made shallow exits usable ([Intelligence ladders](https://cactuscompute.com/blog/intelligence-ladders)). But that was a 3,000-step study, and Needle slices *distinct* nested layers, which is not the same as iterating one shared block. Reef also adds a feedback loop none of these models have: its memory S changes on every pass. Writing to S once per token rather than once per pass removes it.

## Wording robustness comes from data, correctness from execution

ARCHITECTURE.md says the JEPA loss "attacks the wording problem directly". The evidence does not support that. LLM-JEPA adds λ·(1 − cos) between a predicted text embedding and the code embedding. It lifted Llama-3.2-1B on NL-RX-SYNTH from **57.3 to 71.5%**, but OLMo-1B (already at 87.1%) gained only 0.4, and Spider rose 3.0 points, within about 1.5 standard deviations ([LLM-JEPA](https://arxiv.org/html/2509.14252v2)). Every model tested has at least about 1B parameters. Training costs about twice as much. There is no out-of-distribution test: NL-RX is trained and tested within each split, never SYNTH→TURK. And an InfoNCE variant scored **34.4, below the 57.3 baseline**. The interventions with evidence for kural's situation, a parser trained on templates and failing on natural wording, are on the data side. AutoQA paraphrases synthetic data and keeps a paraphrase only if the parser maps it back to the same program. That brought synthetic-only parsers to within 5.2-6.4 points of parsers trained on human data, and the **filter alone was worth 18 points** ([AutoQA](https://arxiv.org/pdf/2010.04806)). Projecting unseen utterances onto the nearest synthetic one beat synthetic-only seq2seq on Overnight (0.37 vs 0.19) ([Marzoev et al.](https://arxiv.org/abs/2004.13645)). On Spider-Syn, explicit synonym annotation recovered more than adversarial training did (62.6 vs 58.5) ([Gan et al.](https://arxiv.org/abs/2106.01065)). Kural's local index of man pages and tldr is a natural source for that kind of alias annotation. As a reranker, JEPA energy has no hard negatives. Nothing makes `-mtime +7` and `-mtime -7` score differently, so it is at most one feature for the confidence head. I-JEPA and V-JEPA are vision methods and are background only ([I-JEPA](https://arxiv.org/abs/2301.08243)).

Execution is the proven route to correctness. Execution-guided decoding prunes beam candidates that fail when run, and lifted WikiSQL to 83.8% ([Wang et al.](https://arxiv.org/abs/1807.03100)). LEVER's verifier, trained on execution results, adds 4.6-10.9 points ([LEVER](https://proceedings.mlr.press/v202/ni23b)), and it **stops helping when execution results are removed** ([Hassid et al.](https://arxiv.org/pdf/2404.00725)). Execution RL works at 8B+: GRPO on Qwen3-8B raised held-out Unix CTF solves from 11.6% to 43.6% ([unix-ctf](https://arxiv.org/abs/2605.29115)), and RLEF set the CodeContests state of the art at 8B/70B ([RLEF](https://proceedings.mlr.press/v267/gehring25a.html)). No execution RL result exists below 100M parameters or for single-step command generation, and reward hacking in shell sandboxes is now being benchmarked ([arXiv 2605.02964](https://arxiv.org/html/2605.02964v1)). Reef's grammar rules out many hacks (printing the answer, `|| true`), but a few defences are still needed. Use at least two randomised file trees per task, run the checker outside the sandbox, and penalise extra deletions asymmetrically. Use a fresh namespace for every candidate: InterCode's reset bug shows that reusing an environment drifts ([Westenfelder et al.](https://aclanthology.org/2025.naacl-long.555.pdf)).

Confidence heads rank well in-domain and degrade off it. A fine-tuned text-to-SQL verifier reached AUROC **0.77-0.79 in-distribution and about 0.66 on unseen schemas**, and scaling to 7B did not close the gap ([arXiv 2607.06799](https://arxiv.org/abs/2607.06799)). Needle takes the minimum of its head's score and the decode probability. It warns that correct Spanish calls scored 0.0, and its head is lost after fine-tuning ([Needle confidence](https://cactuscompute.com/blog/needle-confidence)). Jev is a hosted, closed, early-access decision API. It returns Choice and Score answers with probabilities, and its vendor says it is trained with "RL for calibrated decisions", but there is no published architecture or calibration data ([TypeSafe docs](https://docs.typesafe.ai); [primer](https://docs.typesafe.ai/introduction/machine-learning-primer.md)). Its homepage's own example does not reproduce its "193.6x faster" claim ([typesafe.ai](https://typesafe.ai)).

## On a cache-resident model, integer arithmetic beats ternary weights

Kural's current int8 kernel (`engine/src/kernels.rs`) widens each int8 weight to float32 and still issues float FMAs. It reads fewer bytes but executes more instructions. That is most likely why the int8 variant ran about 30% slower, since the model fits in cache and is bound by compute, not memory (this is a reading of the code, not a measurement). True W8A8 with `vpdpbusd` performs 32 u8×s8 multiply-adds per instruction, against 8 for a float32 FMA, which is the trick NNUE's dense layers use ([nnue-pytorch](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)). INT8 BERT-class encoders on CPUs reach up to 5.8× throughput with negligible accuracy loss ([arXiv 2608.18182](https://arxiv.org/abs/2608.18182)). Hadamard rotation makes 8-bit lossless with plain rounding and no calibration ([QuaRot](https://arxiv.org/abs/2404.00456)). BitNet b1.58 is the wrong tool at this size. Its parity with FP16 holds "from 3B" ([BitNet b1.58](https://huggingface.co/papers/2402.17764)), but at 6-48M ternary models have about **half the effective capacity**: at 6M, perplexity is 77.8 for 16-bit against 116.6-130.1 for ternary ([BitNet Reloaded](https://arxiv.org/html/2407.09527v1)). bitnet.cpp's 2.37-6.17× speedups come from saving memory bandwidth on multi-billion-parameter models ([bitnet.cpp](https://huggingface.co/papers/2410.16144)), which does not apply here. If file size ever matters, ParetoQ's recipe is better: full-precision training, then QAT at 2-3 bits for the last ~10% of training ([ParetoQ](https://arxiv.org/html/2502.02631v2)).

NNUE's incremental accumulator works because its first layer is linear in sparse inputs. In Reef, only the embedding-plus-Engram sum is literally an accumulator. The causal convolution and the delta memory can cache their state, so appending a word costs one step. The iterated passes and the bidirectional pointer attention must be recomputed, which is cheap at 44 tokens. HEAR's hybrid cached encoder cut streaming FLOPs by 3.5× ([HEAR](https://aclanthology.org/2023.findings-acl.257.pdf)). But at about 1.3 ms per full request, live preview may need none of this. NNUE's sparse-input layer (a bitmask of nonzero inputs, then only those columns) is the right kernel for k-WTA outputs. Differentiable logic gate networks are extremely fast on images (over a million MNIST images per second on one core) ([difflogic](https://arxiv.org/abs/2210.08277)), but weak on language: 5.00 BLEU, falling to 4.39 after conversion to discrete gates ([RDDLGN](https://arxiv.org/abs/2508.06097v1)). A linear decline/route head on the pooled encoder state costs microseconds anyway.

## Changes the evidence implies for ARCHITECTURE.md

**Section 3.2 step 2 and the 4.3 Needle row.** Remove "Needle's Hadamard MLP" as the source of the lift. Needle never lifts: its Hadamard MLP is a square, width-preserving mixer of about 25K parameters, and 70.8M of Needle's 121M parameters are Engram tables. Make the lift an open choice between four arms tested at equal FLOPs and at equal parameters: a dense lift at N = 4-8k (the baseline), Monarch/BTT, product-key selection, and Kronecker/Hadamard. Report neuron usage and code overlap alongside accuracy. The 0.3M "structured lift" line in Section 5 should be replaced with a figure per arm. A dense 128×16k int8 lift is about 2.1M MACs per token per pass, which is over budget but not prohibitive.

**Section 4.3 BDH row and Section 6 ladder.** State that BDH's evidence covers a ReLU lift (about 5% active), additive Hebbian memory and dense matrices, and starts at 10M parameters. Add "BDH as published, at equal parameters" as a ladder step before Reef's changes. Then ablate k-WTA vs ReLU, delta vs additive write, and structured vs dense lift one at a time.

**Section 3.2 step 4 (memory write).** Use Gated DeltaNet's form, with a data-dependent decay α_t and β_t = σ(W·x_t), optionally times a trust/outcome factor. Drop "importance × surprise". L2-normalise the k-WTA keys. Keep S in a higher-precision accumulator, or use stochastic rounding, instead of plain 8-bit. Count the state's memory honestly: up to 4.2M numbers per head at N = 32k. Write to S once per token, not once per pass. Mark pruning as unvalidated.

**Section 3.3 and Section 7.** Add a bounded exact softmax buffer over recent session tokens for exact recall such as "the same file as before". This is the hybrid the evidence favours. Use the delta state for soft preferences and patterns.

**Section 3.2 step 7.** Replace "stop when the neuron pattern stops changing" with a KL tolerance on the output head plus a hard cap of 6-8 passes and hysteresis. Train with a random number of passes and with a loss at every pass, plus KL toward the final pass. Monitor loss at r = 1 vs r = max and the correlation between token states. Note that Needle's ladder slices distinct layers, which differs from iterating one block.

**Section 3.1 Engram.** Downgrade it from a component to a test. Use one early site, 1-, 2- and 3-gram orders, prime table sizes, several hash heads and normalised token IDs. Measure on a paraphrase split against putting the same parameters into the embedding or the core.

**Section 4.3 JEPA row.** Replace "attacks the wording problem directly" with "an auxiliary regulariser with evidence only at ≥1B and in-distribution". Insert **paraphrase augmentation with a round-trip filter** before JEPA in the ladder: local 8-14B paraphrases, kept only if the current parser maps them back to the same program. Add alias annotations from the local index. Drop "the same energy can rank candidates", or make it one confidence-head feature.

**Section 4.3 TRM/HRM row.** Replace "beat far larger language models" with: the training recipe (deep supervision, full backprop through the last cycle, EMA) is the transferable part; the ARC gains depend on puzzle IDs, voting and the refinement loop; there is no evidence on language.

**Sections 4.1.4 and 4.3 BitNet row.** Replace "ternary from the start" with "W8A8 integer kernels with Hadamard-rotated activations". If file size matters, use ParetoQ-style low-bit QAT at the end of training. Fix the int8 kernel so it does integer arithmetic.

**Section 4.3, other rows.** NNUE: the accumulator applies only to the embedding/Engram sum and causal state; measure whether live preview needs it at all. Product keys: a candidate lift mechanism, not a large memory. Hopfield: a sizing tool. VSA and logic gates: drop as components; the router and decline heads are probe heads like Needle's. Jev: describe it as "hosted, closed, early-access; calibration claimed by vendor, not published".

**Section 4.2.** Mark fast weights saved across sessions as experimental. Gate them behind an age and size cap and a reset, and keep trusted corrections and untrusted retrieved text in separate states or heads.

**Section 6 evaluation.** Use NL2SH-ALFA's 600-pair test (MIT) as the public benchmark instead of NL2Bash's test split, plus kural's own people-written set. Deduplicate all training data against both. Score strict execution accuracy: the file-system state delta must match exactly and the stdout predicate must hold, on at least two seeded file trees. Also report InterCode's continuous reward for comparability. Report AUROC, ECE and the risk-coverage curve for the confidence head, including on held-out tool families.

**Section 3.6.** Execute only complete candidates on the open-bash path; prune typed programs stage by stage. Treat empty output as a ranking feature, because "are there any core dumps?" can correctly return nothing.

## Recommended experiment order

The order follows one rule: build what measures everything first, then make the cheap changes with strong evidence, and only then the novel core, whose evidence is weakest. Each step keeps the ladder's "keep only if it helps" rule, uses at least three seeds (LLM-JEPA's baselines vary by ±5 points), and is scored on the untouched test sets.

| Step | Experiment | Why at this point |
|---|---|---|
| 1 | Evaluation harness: NL2SH-ALFA test plus kural's people-written set, strict execution checker in fresh bwrap namespaces, local Qwen/Llama 8B-14B baselines with the best wrapper and with the grounding variant | Every later step needs it; it also tells you where 0.2 already stands |
| 2 | Integer W8A8 VNNI kernel on today's model (in parallel; engineering only) | 2-3× on matrix multiplies buys headroom for everything that follows |
| 3 | Data: filtered NL2SH-ALFA train and tldr, paraphrase augmentation with round-trip filter, alias annotations from the local index; local index plus open bash form | The strongest evidence for kural's actual weakness |
| 4 | Execution-guided pruning and a confidence head trained on sandbox outcomes, on today's network | Independent of the core; gives calibrated ranking for every later step |
| 5 | Cheap attention changes in today's model: QK-norm, sigmoid output gate, 3-tap q/k/v convolution | Near-free, with direct evidence |
| 6 | JEPA auxiliary loss (cosine, tied predictor), λ ∈ {0.5, 1, 2}, watching for collapse | Cheap, but only if it adds points over step 3 |
| 7 | Pretraining on English and Stack Exchange | Prerequisite for comparing cores fairly |
| 8 | Core: transformer vs BDH as published at equal parameters; then k-WTA vs ReLU, delta vs additive, and the four lift arms | Tests the untested departures one at a time |
| 9 | Recurrent depth with the Geiping/TRM recipe; sweep passes 1-8; KL-threshold exit with a cap | Shows whether passes help at a few million parameters |
| 10 | Engram, one early site, vs equal parameters spent elsewhere | Small expected gain; measured on the paraphrase split |
| 11 | Session memory: gated delta within a session plus an exact session buffer; persistence across sessions last | Needs session-shaped training data |
| 12 | GRPO execution RL with asymmetric penalties and randomised file trees | Only after supervised training saturates |
| 13 | Final low-bit QAT, only if file size matters | Last, because it costs accuracy |

## Conclusion

Taken together, the evidence turns Reef from an architecture bet into a measurement programme. The parts with the strongest support (data augmentation with round-trip filtering, grammar-constrained output, execution checks and integer kernels) improve today's 3.6M model without touching the core at all. Kural could therefore have a credible 8B comparison before building any BDH machinery. That also guards against a real risk: if the novel core is built first, any gain or loss becomes impossible to attribute.

The deeper finding is that Reef's novelty sits exactly where the literature is silent: sparse delta-rule memory under k-WTA keys, iterated at a few million parameters, for parsing. The two most-cited inspirations do not cover it. Needle moved its capacity into attention and lookup tables rather than a wide lift, and BDH's results stop at 10M with a different memory and lift. If Reef works, kural will be producing the first evidence for that combination. The ladder therefore matters more than any single component: it is the only way to find out which part of the claim is true.
